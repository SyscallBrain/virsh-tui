## P0 — wrong target, data loss, guest outage

### P0-1 `ZZ` (documented quit) runs managed-save on the first `Z`
- Evidence: `probe p0_1`. One `Z` on the dashboard submits `managedsave` for the selection — with marks, for **every marked VM** (the fixture submitted it for three).
- Path: `handle_key` only arms `pending_quit_z` (`src/app/mod.rs:1659`, `2239-2245`); the same key then reaches `engine.feed` (`mod.rs:1771`), where `["Z"]` is a full binding (`src/input/keymap.rs:37`), submitted without confirmation (`mod.rs:2014-2030`). `docs/DECISIONS.md:28` assumes the first `Z` never reaches the engine.
- Fix: do not dispatch a lone `Z` immediately (resolve it on the sequence timeout like pending digits), or move managed-save to another key; add a confirmation either way. Update `book/src/keys.md` and `DECISIONS.md`.

### P0-2 Selection jumps to another VM on every refresh under CPU / uptime sort
- Evidence: `probe p0_2` (cursor on `a`, one sample later it is on `c`).
- Path: `apply_live_msg` (`src/app/live.rs:108-120`) calls `apply_summaries` first; `from_summaries` rebuilds rows with `cpu_frac = 0.0` and `uptime = "—"` and `select_name` stores an **index** in that order. Uptimes and `apply_metrics()` are applied afterwards and reorder `visible_rows()`.
- Effect: `S`/`r`/`p`/`D` hit whichever VM is under the hopping cursor.
- Fix: track the selection by name, or re-select after metrics and uptimes are applied. `Sort::Uptime` also sorts the display string (`dashboard.rs:308`: `"10h 00m" < "2m" < "3d 04h"`); keep seconds in `DomainRow`.

### P0-3 Stale `self.detail` is used as the target outside the Detail view
- Evidence: `probe p0_3` (dashboard selection `arch-dev`, picker target `stale-vm`).
- Path: view keys leave Detail via `switch_view` without clearing `self.detail` (`mod.rs:1772`, `981`). Then:
  - `request_picker` (`src/app/requests.rs:365-375`) → media inserted/ejected on the wrong VM.
  - `open_async_palette` (`requests.rs:960-964`) → commands prefilled with the stale domain.
  - `sync_poller` (`mod.rs:790-797`) → config and IP are never fetched for the new dashboard selection.
  - Opening any domain replaces `self.detail`, silently dropping unsaved hardware edits.
- Fix: one `current_domain()` helper that uses `detail` only when `view == View::Detail`; decide what leaving Detail with pending edits does (see P1-9).

### P0-4 Sizes are passed to virsh verbatim; bare numbers mean KiB there
- Evidence: `probe p0_4`: Memory `8192` → `setmem vm 8192 --live --config`; disk size `200` → `blockresize vm vda 200`; an **empty** vCPU field → `setvcpus vm 1 --live --config`.
- Path: `HardwareState::will_run` (`src/ui/views/detail/hardware.rs:694-750`), builders `src/command/builders/hardware.rs`. The app's own parsers disagree on a bare number (`size_to_kib` = MiB at `hardware.rs:85`, `parse_size_mib` = bytes at `widgets/form.rs:11`); virsh reads KiB. `Field::valid()` is never called.
- Effect: 8 MiB balloon target on a running guest; a block device resized to 200 KiB. There is no shrink guard, also not for `:block-resize`.
- Fix: parse once to KiB and emit an explicit unit; reject empty/invalid/unit-less input before `:w`; refuse or strongly confirm a `blockresize` below the current size; enforce `Field::valid()` and number ranges on typed input.

### P0-5 `:attach-disk <vm> <src> <target>` attaches every image as raw
- Evidence: `probe p0_5` → `attach-disk debian-bookworm /x.qcow2 vdb --live --config`, no `--subdriver`.
- Path: `ex_job_plans` → `hardware::attach_disk(.., true, true)` (`src/app/jobs.rs:1362-1365`). Only the `␣da` prefill carries `--driver qemu --subdriver qcow2` (`src/app/domains.rs:464-467`).
- Effect: a qcow2 file is exposed raw; guest writes corrupt it. *(libvirt's raw default is from knowledge, not reproduced.)*
- Fix: detect the format (`vol-dumpxml` / `qemu-img info`) or require it.

### P0-6 Volumes are labelled `⚠ orphan` from incomplete data
- Evidence: `code`. `disk_sources` (`live.rs:662-676`) is a line scanner that only sees `file=`/`dev=`, ignores `<source pool= volume=>` disks, does not unescape entities and reads `--inactive` XML only; backing references are counted inside the selected pool only (`live.rs:632`).
- Effect: in-use volumes can be shown as orphans next to the `X` delete key.
- Fix: parse with `roxmltree`, resolve pool/volume sources, include live XML, count backing references across pools, and soften the label.

### P0-7 Confirmation routing by label text
- Evidence: `probe p0_7`: with the "delete volume" confirmation off, Storage `D` runs `pool-destroy nvme-fast` with no modal.
- Path: `apply_confirm_settings` derives the verb from `confirm_label` (`mod.rs:601-621`); pool destroy uses title `⚠ Delete` / label `y delete` (`src/app/storage.rs:131-166`). Network destroy/undefine follow the *domain* toggles the same way. `D` is also a no-op when the pool has no volume selected (`storage.rs:127`).
- Fix: an explicit `ConfirmKind` in `Confirm`; own title and label for pool destroy; do not gate it on a selected volume.

- **P1-41 `Ctrl-Z` inside the editor or console deadlocks the terminal.** `pty` (editor state `T`, TUI still polling, tty foreground group = editor, keys ignored). `run_foreground` gives the child its own foreground process group and polls only `waitid(WEXITED)` (`src/app/external.rs:140-176`), so a job-control stop is never noticed. ## P2 — robustness

- **RB-1 Arithmetic overflow on very small terminals (debug builds only).** `probe r2_small_terminal_panics`: in a debug build the help overlay at heights ≤ 5 (`overlays/help.rs:253-275`), the which-key popup below about 23 columns or 10 rows (`src/app/render.rs:38-39`) and the wizard at 1×1 panic with "attempt to subtract with overflow". The same sweep with `--release` produced no panic, so shipped binaries do not crash; the wrapped coordinates are still wrong. All other views, tabs and modals drew at all 19 sizes in both profiles. Use saturating arithmetic and skip overlays under the TooSmall breakpoint.
- **RB-10 The panic hook tears down the terminal for worker-task panics the app survives.** `code`: the global hook leaves the alternate screen and raw mode (`main.rs:101-108`) on any panic, including a panicking job/selection/load task that `finish_job` reports and continues from (`jobs.rs:1201`, `mod.rs:325`). The TUI then draws on the main screen in cooked mode. Restore the terminal only for main-thread panics, or re-enter after a task panic.
- **RB-11 Duplication in job submission.** `code`: nine `submit_*` functions repeat the busy check and a 17-field `ActiveJob` literal (`jobs.rs:292-1002`; `submit_hardware` already diverges by returning true when busy). One `admit_job(plans, future)` helper would remove roughly 400 lines.
- **RB-2 Unbounded repeat counts.** `probe r2_count`: `3000000j` blocks the UI for 3.5 s (debug, 15 rows); the count is a `u32` (`mod.rs:1807,2179`). Clamp and move by `delta * count`.
- **RB-3 Drain can outlive the child.** `code`: after the leader exits, stdout/stderr are awaited until the full timeout if a detached grandchild holds the pipe (`process.rs:229-246`).
- **RB-4 Input-thread pause race.** `code`: the thread sets `INPUT_IDLE=false` after checking `INPUT_PAUSED` (`external.rs:39-45`) and can still read stdin while the editor owns the terminal.
- **RB-5 Config handling.** `code`: an invalid `config.toml` falls back to defaults with only a log line, and the next settings change overwrites the user's file (`config.rs:201-212`); writes are not atomic.
- **RB-6 Logging.** `code`: `File::create` truncates the log on each start, falls back to a predictable `/tmp/virsh-tui.log`, and a failure aborts startup (`main.rs:110-128`).
- **RB-7 Safety-snapshot name collides** (`auto-before-revert-HHMM`, `builders/snapshot.rs:22-28`). `code`.
- **RB-8 XML define path drops CDATA and mixed content** (`xml/edit.rs:52-78`). `code`.
- **RB-9 Dead code**: `parse_help::{load_index, load_doc}`, `exec::run_blocking`, `exec::run_raw` and `command::exec::execute` (tests only); `fetch_index` writes a cache nothing reads; the live-mode "✗ … request was not submitted" branches in `ex.rs:231`, `detail.rs`, `networks.rs`, `storage.rs`, `domains.rs` are unreachable; `external.rs` re-implements `process.rs`'s exit observation.

## P2 — performance (all `code`)

- **PF-1 N+1 sequential `virsh` spawns on the navigation path.** Networks: `domiflist` for every domain on every network selection change (`live.rs:346-362`, from `mod.rs:1908`). Storage: `vol-dumpxml` per volume on every pool selection change (`live.rs:624-631`), plus `dumpxml --inactive` per domain and `vol-list` twice per load (`live.rs:547-602`). Cache per view load, fetch details lazily or with bounded concurrency.
- **PF-2 Poller does not coalesce selection requests** (`poller.rs:102-125`): holding `j` queues one `dumpxml` per row, each delaying the stats tick.
- **PF-3 Two `virsh` processes per tick** (`backend/virsh/mod.rs:38-48`); over `qemu+ssh` that is two SSH sessions per second. Refresh autostart every N ticks; consider one long-lived `virsh` session.
- **PF-4 `domstats` has no `--nowait`.** A domain holding a long job can block the call until the 30 s timeout, reported as "lost connection … retrying" (`live.rs:131-134`). *(libvirt behaviour from knowledge.)*
- **PF-5 Event streams respawn every 2 s forever** when virsh exits at once: `stream_once` returns `Ok` on EOF and resets the backoff (`backend/virsh/events.rs:116-126`). Five streams per connection; `net-event --event metadata-change` is missing on older libvirt.
- **PF-6 `visible_rows()` re-filters and re-sorts about 8× per frame** with a `String` clone per comparison (`dashboard.rs:296-311`).
- **PF-7 `observe_exit` polls `waitid` every 10 ms per child** (`command/process.rs:88-114`), including 24 h jobs.
- **PF-8 Wizard autosaves to disk on every key** on the UI thread (`wizard.rs:117,164-166`).
- **PF-9 Entering Host/Networks/Storage waits for the 1 s tick** (`mod.rs:866-872`); these views never refresh while open.
- **PF-10** `EventsState::push` does `Vec::remove(0)` at the 5000 cap (`ui/views/events.rs:131-136`); `ingest_domains` is O(n²) on names and clones `Counters` per domain per tick (`metrics/store.rs:240-272`).
